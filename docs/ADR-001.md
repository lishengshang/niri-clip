# ADR-001：原生 UI 技术栈与进程形态

状态：已接受（M5.1，2026-08-28） · **修订 1（M5.3，2026-08-28）：渲染器与窗口类型** · 关联：docs/NATIVE-UI.md、epic #8 / PR #9

## 修订 1：layer-shell → 常规 xdg 窗口（tiny-skia 软渲染）

真机反馈驱动的两次推翻：
1. **NVIDIA wgpu 冻结**（上游 #360）：SurfaceError 后不重建 surface，首帧后
   UI 永久冻结 → 先尝试 GL 后端，EGL 初始化仍失败 → **tiny-skia 纯软件渲染**
   （列表 UI 无 GPU 需求，二进制 -1/3，与显卡驱动彻底解耦）
2. **layer-shell 的三个结构性缺陷**：
   - 无法被 niri window-rule 约束（用户无法自定义悬浮/位置/边框）
   - exwlshellev daemon 运行器缺 IME 接线（multi_window 私有不可达）→ 中文搜索不可用
   - 窗口管理（关闭旧实例等）要自己造轮子

**修订决策**：改用 iced winit 常规 xdg 窗口（app-id = `niri-clip-gui`），
悬浮/位置/边框/阴影/透明度由用户 `rule.kdl` 的 window-rule 约定；
winit 原生 IME → 中文搜索解锁；tiny-skia 软渲染保留。

## 原决策（仍然有效的部分）

- 进程形态 **A 按需进程**：`niri-clip tui` 拉起，Mod+V 零绑定改动
- 框架选 iced 生态（0.14），GTK 系仍被否决

## 被拒备选

| 备选 | 拒因 |
|---|---|
| layer-shell（exwlshelleventloop daemon） | IME 缺失 + 无法被 window-rule 约束（本次修订的动因） |
| gtk4-layer-shell（Rust 绑定） | GTK 闭包过重；iced 修订后无必要 |
| smithay-client-toolkit 手写 | 工作量与长期维护成本不成比例 |

## 验证与回退

- IME 中文输入、悬浮参数、图片预览：真机验证项（用户 rule.kdl 可调）
- 窗口启动延迟纳入开销预算表（目标 ≤50ms），M5.4 进基准
