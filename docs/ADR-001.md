# ADR-001：原生 UI 技术栈与进程形态

状态：已接受（M5.1，2026-08-28） · 关联：docs/NATIVE-UI.md、epic #8 / PR #9

## 决策

1. **框架：iced_exwlshell 0.19**（waycrate/exwlshelleventloop 生态，iced 0.14 绑定）
2. **进程形态：A 按需进程**——`niri-clip gui` 每次 Mod+V 起新进程创建 layer surface

## 理由

- **活跃度**：上游 2026-07 仍在发版与合 PR（74 个 crate 版本），支持 layershell /
  popup / session-lock / ext-virtual-keyboard，niri（wlroots 系合成器）为其目标场景
- **纯 Rust**：无 GTK C 依赖闭包，符合产品原则 2（低开销）与 1.8 依赖审计门槛
- **选型依据**：与 iced 0.14 对齐的 Elm 架构让 UI 层保持"只做渲染"的分层约定；
  文档示例完整可参照，spike 成本低
- **形态 A**：启动路径 = 进程 exec + layer surface 创建（预计 10–30ms），
  内存随退出归零，无状态同步复杂度——PoC 数据若显示不达标再议形态 B

## 被拒备选

| 备选 | 拒因 |
|---|---|
| gtk4-layer-shell（Rust 绑定） | GTK 全家桶闭包过重，违背低开销；仅作 iced 路径遇硬阻塞时的回退 |
| smithay-client-toolkit 手写 | 工作量与长期维护成本不成比例，预览/键盘/IME 全自建 |

## 验证与回退

- **IME（zwp_text_input）为 M5.2 真机必测项**：搜索框需中文输入；若 iced 路径
  无法支持，按本文档回退 gtk4-layer-shell 重新 spike（数据记 NATIVE-UI.md）
- 窗口启动延迟纳入开销预算表（目标 ≤50ms），M5.4 进 criterion 基准
